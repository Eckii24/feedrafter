## D4/C19 — local subtitle selection, WebVTT parsing and cue normalization foundations only

`src/server/domain/transcript-cues.ts` is an unwired pure helper. It requires a finite positive duration no greater than `Number.MAX_SAFE_INTEGER` seconds and finite half-open cue intervals within that duration; invalid intervals or empty/whitespace-only text throw. It collapses ASCII space, tab, CR and LF, orders by start/end/text, and unions strictly overlapping cues only when their normalized whole text is identical. It preserves language, method and duration, distinct or merely touching cues, and uncovered gaps. It does not infer word-level alignment, deduplicate partial text, repair invalid data, validate subtitle quality, or establish transcript completeness.

`src/server/domain/webvtt.ts` adds an unwired, dependency-free parser for caller-supplied text. It requires a `WEBVTT` header (optional BOM and header description), an empty separator line before blocks, and a caller-provided nonnegative safe-integer UTF-8 byte limit and finite positive duration. Empty input is invalid; a header-only document is a valid empty transcript. It accepts CR/LF line endings, optional cue IDs, the standard `MM:SS.mmm` and `HH:MM:SS.mmm` forms (at least two hour digits, safe integer milliseconds), and the supported `vertical`, `line`, `position`, `size`, `align`, and `region` settings. NOTE blocks may occur among cues; STYLE and REGION blocks must precede cues. Block contents are not interpreted, and arrows inside metadata are rejected to avoid hiding cue timings. Header metadata lines, unsupported settings or structures, malformed intervals, and empty or whitespace-only cue text fail closed. Only exactly empty lines delimit blocks.

Cue text supports balanced `b`, `i`, `u`, `c` with optional classes, `v` with nonempty speaker annotation without entity escapes, `lang` with language annotation, `ruby`, and `rt` tags, and the named WebVTT entities `amp`, `lt`, `gt`, `nbsp`, `lrm`, `rlm`. Tags are removed, entity values decoded once, and text passed to `normalizeTranscriptCues`; unsupported tags (including inline timestamps), entities (including numeric references), malformed nesting and literal unescaped markup fail closed. This deliberately supports a strict subset, not every valid WebVTT file; no subtitle quality or completeness guarantee follows. Language and method are supplied unchanged by the caller, not inferred or validated by the parser.

`src/server/domain/subtitle-selection.ts` is an unwired pure candidate selector. It accepts an array of plain records with exactly `id`, `language`, `format` and `provenance`; no URL, endpoint or other field is accepted. IDs are nonempty, unique, case-sensitive opaque ASCII tokens (`A-Z`, `a-z`, digits, `.`, `_`, `~`, `-`), never interpreted as locations. ## Local partial C13 context preparation slice

`src/server/application/prepare-context.ts` is a standalone planner, not runtime wiring. It applies the existing score context flags, sizes its exact JSON envelope (prompt, questions, tool-schema text and selected fields) plus explicit framing and output reserves, and produces either a direct request or gapless, non-overlapping chunks. Paragraph and supplied time boundaries are preferred; oversized text splits at Unicode code-point boundaries. Coverage uses half-open UTF-16 offsets; timestamps are reported only at supplied exact boundaries. IDs bind article/revision, generation, task, selected inputs, text, time boundaries and intervals. No excluded article fields are inserted into the request. Unselected content has no coverage requirement. Invalid or unfit requests fail rather than truncate.

The provider tokenizer, when supplied, counts the returned serialized envelope. Otherwise one token per UTF-8 byte is used as a conservative estimate **only for tokenizers that emit at most one token per byte**. Integration must send that exact envelope, supply adequate additional provider framing/tool protocol reserve, verify the tokenizer assumption and enforce actual provider limits. Tools are represented as a JSON text string in this envelope, not as provider-native tool objects. Chunk selection is greedy; unusual non-monotonic tokenizers may cause a visible failure even when another partition would fit. These contracts are not evidence of provider request accounting or runtime readiness.

A fresh reviewer measured an impossible-overhead request with 40,000 content characters at 1.436 seconds synchronous time and approximately 803 MB serialized before rejection. The user authorized this repair. The planner now checks the fixed envelope with empty selected content, including all selected metadata and reserves, against both limits before sizing full content or searching prefixes. A provider tokenizer may be non-monotonic: even if adding content could reduce its count, an unfit fixed envelope is rejected. Provider prefix search has a plan-wide limit of 4,096 probes and 16 MiB of conservative serialized-byte work (fixed-envelope UTF-8 bytes plus six bytes per UTF-16 content unit per probe); the next probe fails visibly before serialization. This covers binary, exhaustive fallback, preferred-boundary and final chunk sizing, not the one fixed and one full-content request or arbitrary tokenizer-internal work. Accepted plans retain exact coverage and boundary checks.
